# 订单列表页（筛选 + 排序 + 勾选 + 导出入口）Spec

> 状态：**已批准**（2026-09-03；阶段一 / 共四阶段：spec → plan → task → checklist；本迭代仅产出方案文档，不写实现代码）。
> 关联契约：后端查询契约 `docs/order-query-design.md`（定稿）、导出创建契约 `docs/be-td.md` 4.5、
> 产品需求 `docs/prd.md` 7.1–7.4、前端技术设计 `docs/fe-td.md`。

## 背景

订单查询后端接口已按 `order-query-design.md` 定稿实现：分页 + 8 项条件筛选（AND 语义）+ 排序白名单，
响应回显实际生效排序。前端 `features/orders/api.ts` 的查询参数类型与序列化已完整就绪，
但 `OrderListPage` 目前只接入分页：筛选表单、表头排序、勾选、导出入口均未实现。

导出任务创建接口（`POST /api/v1/export-jobs`）后端尚未实现，但请求/响应契约（含幂等键、
勾选/筛选两种导出模式）已在 `be-td.md` 4.5 定稿。本方案按该契约完整设计前端导出入口，
接口未就绪期间以错误提示兜底，不阻塞页面其他能力。

## 目标

1. 运营人员可按 8 项条件组合筛选订单、按 3 个展示列排序、分页浏览结果。
2. 筛选草稿与已提交查询严格分离：输入过程不触发请求、不改变列表数据与导出范围。
3. 支持跨页勾选（上限 1000 条），并从页面发起「导出已选」「导出筛选结果」两类异步任务的创建。
4. 查询失败、创建失败等异常下保留用户意图（草稿、已提交条件、勾选），可重试。
5. 全部界面使用现有 antd 组件库搭建，PC 布局，与现有页面风格一致。

## 核心状态原则（本方案的强约束）

1. **草稿 ≠ 已提交**：筛选草稿是正在输入的条件；已提交条件是点击「查询」后真正请求后端的条件。
   输入框随便改，列表与导出范围不乱变。
2. **本地状态 ≠ 服务端数据**：筛选草稿、弹窗、勾选集合是本地界面状态；订单列表是服务端返回的事实，
   只能通过查询流程获得。
3. 状态迁移规则（唯一事实源，功能需求与验收标准均由此推导）：

| 触发 | 草稿 | 已提交条件 | 页码 | 勾选 |
|---|---|---|---|---|
| 点查询 | 不变 | ← 复制草稿 | 回到第 1 页 | 不变 |
| 点重置 | 清空 | 清空 | 回到第 1 页 | 清空 |
| 换页 / 改每页条数 | 不变 | 不变 | 仅分页变化 | 不变 |
| 查询失败 | 不变 | 不变 | 不变 | 不变，仅显示错误 |
| 导出创建成功 | 不变 | 不变 | 不变 | 清空 |
| 导出创建失败 | 不变 | 不变 | 不变 | 不变，弹窗保留可重试 |

补充裁定：每页条数属浏览偏好，「重置」不还原它；表头排序不属于草稿，点击立即作用于已提交查询。

## 功能需求

### 筛选与查询

- **F1** 筛选区提供 8 项条件输入，语义与后端查询契约一一对应：
  订单状态 / 销售渠道 / 币种（可多选，不选 = 不过滤）；订单号（前缀匹配）、客户姓名（模糊匹配）、
  客户手机号（精确匹配）；订单金额区间（下界 / 上界可只填一端）；下单时间区间（含时刻、左闭右开，
  提供常用快捷预设）。
- **F2** 筛选区提供「查询」「重置」：「查询」将当前草稿复制为已提交条件并回到第 1 页
  （排序语义保持不变）；「重置」清空草稿与已提交条件、回到第 1 页并清空勾选。
- **F3** 草稿变化不触发任何请求，不影响列表数据与导出范围。
- **F4** 换页或修改每页条数仅改变分页参数，筛选与排序语义原样保留。
- **F5** 表单校验与后端契约对齐：金额区间两端都填时下界 ≤ 上界；时间区间两端都填时开始 < 结束；
  手机号须为 11 位数字。校验失败阻止提交并给出字段级提示。

### 列表展示

- **F6** 表格展示列对齐 PRD 7.1.1：勾选框、订单号、客户姓名、客户手机号、订单状态、销售渠道、
  订单金额、币种、收货省份、下单时间（在现有列基础上补客户手机号列、币种独立成列）。
- **F7** 枚举值（状态 / 渠道 / 币种）在筛选下拉与表格中以中文标签展示，传输与存储仍用后端枚举名。
- **F8** 订单号、订单金额、下单时间三列支持表头排序（升序 / 降序 / 取消三态），点击立即生效
  并回到第 1 页；默认下单时间降序，「取消」回到默认排序；排序状态以响应回显的实际生效排序对齐。
- **F9** 表格加载中呈加载态；空结果显示空状态；保留手动刷新入口。

### 勾选

- **F10** 行可勾选，翻页后已勾选保留（跨页保留），已选订单数上限 1000；达到上限后再勾选被阻止并提示。
- **F11** 勾选后显示「已选择 N 条」提示与「清空选择」操作。

### 导出入口

- **F12** 「导出已选」：未勾选时不可用；打开弹窗后范围只读展示「已选订单 N 条」。
- **F13** 「导出筛选结果」：以当前已提交条件（非草稿）为范围，弹窗内只读展示「当前筛选结果 N 条」
  （N 取列表当前总数）；后端实际创建时以服务端计数为准。
- **F14** 导出配置弹窗：导出范围（只读）、导出列（9 列白名单多选，默认 6 列，至少 1 列，
  选择顺序即表头顺序）、文件名（可选，默认按时间生成，超 100 字符阻止提交）。
- **F15** 提交创建时生成一次性幂等键随请求发送；提交期间确认按钮禁用防双击。
- **F16** 创建成功：关闭弹窗、清空勾选、成功提示并提供「查看任务」入口（切换到导出任务页）。
- **F17** 创建失败：弹窗与已填内容保留、勾选保留、展示错误信息（含 trace_id），可修正后重试。

### 异常与兜底

- **F18** 查询失败：保留上一次成功数据（若有）并展示错误提示与重新加载入口；
  草稿、已提交条件、勾选全部保留。
- **F19** 创建接口未就绪期间：调用失败走统一错误提示，不影响页面其他功能。

## 非功能需求

- **N1** 界面全部使用现有 antd 6 组件实现，不新增 UI 依赖。
- **N2** PC 布局（≥1280px），筛选区网格排布并支持展开 / 收起，风格与现有 AppLayout 一致、紧凑美观。
- **N3** 时间参数按后端契约序列化（本地时间格式、无时区后缀、左闭右开）；金额两位小数。
- **N4** 所有请求错误提示包含 trace_id。
- **N5** 可测试性：状态迁移、表单值与查询参数映射、勾选上限规则、导出请求构建等逻辑以纯函数抽离，
  在 node 环境单测（延续现有 stub fetch 风格），不引入 DOM 测试基建；`npm test` 与 `npm run build` 通过。
- **N6** 后端导出创建接口的实现进度不阻塞本方案其他能力的开发与验收。

## 不做的事

- 反选模式（表头全选 = 按筛选快照导出、排除订单）——留待导出模块迭代。
- 导出任务页本体（列表 / 进度 / SSE / 下载 / 重试）——本方案仅提供创建成功后的入口跳转。
- 筛选条件 URL 同步与分享、引入路由。
- 省份筛选、列表虚拟化、移动端适配。
- 后端导出创建接口的实现、订单数据变更能力。
- 组件渲染级测试（jsdom / Testing Library 基建）。

## 验收标准

- **AC1** 打开页面：默认无条件查询第 1 页、默认每页条数、下单时间降序；分页总数与列表一致。
- **AC2** 修改草稿但不点查询：无新请求发出，列表与导出范围不变。（网络面板观测）
- **AC3** 点查询：请求携带全部草稿条件（多值逗号拼接、时间本地格式无时区后缀），页码回 1。
- **AC4** 点重置：表单清空、回到无条件默认查询第 1 页、勾选清空、已选提示消失。
- **AC5** 换页 / 改每页条数：请求仅分页参数变化，筛选与排序参数原样保留。
- **AC6** 点表头排序：按所选字段与方向请求并回第 1 页；表头指示与响应回显排序一致；取消后回默认。
- **AC7** 跨页勾选：第 1 页勾 2 条 → 翻页再勾 1 条 → 提示「已选择 3 条」；翻回原页勾选仍在。
- **AC8** 勾满 1000 条后再勾：被阻止并提示上限。
- **AC9** 未勾选时「导出已选」不可用；勾选后弹窗展示「已选订单 N 条」。
- **AC10** 「导出筛选结果」弹窗展示的总数 = 当前已提交查询总数；改草稿不点查询直接导出，范围仍是已提交条件。
- **AC11** 筛选表单校验：金额倒挂、时间倒挂、手机号非法时阻止点查询并给字段级提示。
- **AC12** 弹窗校验：清空所有导出列、或文件名超 100 字符时无法提交，并有提示。
- **AC13** 提交创建：请求体符合 be-td.md 4.5（模式 / ID 或筛选快照 / 列 / 文件名）且携带幂等键头；
  提交期间按钮禁用。
- **AC14** 创建成功：弹窗关闭、勾选清空、出现成功提示与查看任务入口。
- **AC15** 创建失败：弹窗与已填内容保留、勾选保留、错误信息含 trace_id，可再次提交。
- **AC16** 查询失败（如停掉后端）：上一次数据仍在并显示错误与重新加载入口；草稿 / 已提交条件 / 勾选保留。
- **AC17** 新增纯逻辑均有单测；`npm test`、`npm run build` 通过。
