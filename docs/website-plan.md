# FlowHub 展示站设计方案（Website Plan）

> 本文档记录 FlowHub 项目展示站当前实现。视觉方向为 **Signal Rail / 可靠信号轨**：借鉴优秀开发者产品站的完成度、克制留白与真实交互，但不复制其角色、配色或版式。

## 1. 定位与目标

站点承担双职责：

1. **项目展示页**：让技术负责人、面试官和学习者在首屏理解 FlowHub 解决什么问题，并能继续核验其可靠性机制；
2. **复盘文档阅读器**：为 `doc/` 下 12 篇复盘文档提供可检索、可串读、可切换语言的阅读环境。

README 继续负责快速开始与 API 总览，`doc/` 继续作为内容事实源。首页只重组真实工程事实，不另造第二套能力描述。

## 2. 视觉系统

### 2.1 概念

FlowHub 的视觉母题是“多笔数据进入一个受控任务，沿可靠轨道经过检查点，最终发布为可信文件”。Logo、首屏状态轨、执行工作台和导入导出镜像图都复用这套语言。

### 2.2 色彩

| 语义 | 色值 | 用途 |
|---|---|---|
| 墨黑 | `#0D100D` | Hero、事故台账、Footer |
| 暖白 | `#F4F6F1` | 浅色主题画布 |
| 酸性黄绿 | `#DFFF52` | 成功轨道、主 CTA、事实信号 |
| 珊瑚 | `#FF6846` | 品牌标记、当前步骤、关键链接 |
| 冰蓝 | `#64D7E7` | RUNNING、SSE、实时进度 |
| 琥珀 | `#F1B84B` | 待处理、导入语义 |

中性色占页面主体，业务色只在状态和路径上出现。禁止紫青渐变、装饰光球、玻璃拟态和无意义的彩色卡片墙。

### 2.3 排版与形状

- 标题优先使用 `Bahnschrift / Aptos Display`，正文使用 `Aptos / Segoe UI / 中文系统字体`，技术数据使用 `Cascadia Code / Consolas`；
- 字距统一为 `0`，不随视口连续缩放字号，使用明确断点；
- 控件圆角 6px，内容工具面板最大 8px；
- 大区块依靠留白、细线和真实状态形成层次，不使用浮动卡片堆叠。

## 3. 技术与工程

- **框架**：Docusaurus 3 + React 19 + TypeScript；
- **运行要求**：Node 20+，推荐 Node 22；
- **工程位置**：`website/`；
- **内容同步**：`scripts/sync-docs.mjs` 将 `doc/` 同步到 `website/docs/`；
- **资产同步**：`scripts/gen-inline-svg.mjs` 将 `docs/images/` 同步到 `website/static/img/`，并生成架构图内联模块；
- **部署**：`.github/workflows/deploy-website.yml` 发布到 GitHub Pages。

`website/docs/`、`website/static/img/` 和 `src/components/architecture.inline.ts` 都是构建产物或资产镜像，禁止手改。

## 5. 首页分区

### 5.1 Hero：任务状态模型

- H1 直接使用产品名 `FlowHub`，定位与价值主张作为支持文案；
- 主视觉不是装饰插画或整张架构图，而是一条可读的任务状态链：`202 → TX → ACK → CAS → 64K → XLSX`；
- 节点、连接和进度只在首次加载时播放一次，明确标注为演示链路，不冒充性能结果；
- 首屏底部 Signal Rail 同时暴露 20 万行样本、9 列互逆格式、8 类事故防线、DB 事实源与技术栈。

### 5.2 六步执行工作台

- 六个步骤使用标准 ARIA Tab 语义，支持方向键、Home、End；
- 当前步骤同步展示人话说明、真实仓库代码片段和对应复盘入口；
- 段尾强调三条关键不变量：同事务双写、CAS 原子抢占、原子文件发布；
- `MySQL 是唯一事实源` 作为独立结论呈现，而不是装饰 callout。

### 5.3 事故防线台账

8 个可靠性模式改为高密度表格式台账：事故、工程防线、模式标签和深读入口同一行对照。桌面保留扫描效率，移动端按行重排，不依赖 hover 才能理解内容。

### 5.4 性能证据区

- `200,000` 只表示种子脚本的确定性数据规模；
- 耗时、峰值 RSS、文件大小在受控脚本落地前一律显示 `-- / 待实测`；
- 进度条明确写明为交互示意，不与基准数据混淆；
- 保留 `-Xmx512m`、PID/运行令牌、环境与 commit 的采集契约。

### 5.5 导入导出镜像

用两条相反方向的数据链解释 9 列 Excel 格式的互逆关系：导出侧是快照、Keyset、SXSSF，导入侧是 SAX、三层校验、PARTIAL；中央显示双方共用的 Outbox、CAS、租约与 SSE 骨架。

### 5.6 文档收口

首页以全宽深色行动带进入 12 篇复盘，不另做营销卡片。Footer 保留文档、项目与工程规范入口。

## 6. 响应式与可访问性

- 主要断点为 996px、760px、420px；固定格式 UI 使用明确网格轨道，避免动态内容撑动布局；
- 移动端首屏节点由 6 列改为 2 列，工作台 Tabs 改为 2 列，事故台账转为三列紧凑行；
- 所有主要交互热区至少 42px，焦点态使用 2px 珊瑚外框；
- `prefers-reduced-motion` 下关闭路径、数据包、计数与进度动画并直接呈现稳定终值；
- 深浅主题分别定义语义 token，Hero、事故台账与 Footer 保持品牌墨黑，性能区保持证据纸张式浅色。

## 7. 中英文策略

| 层 | 范围 | 策略 |
|---|---|---|
| 导航与 Footer | 全站框架 | Docusaurus i18n 完整翻译 |
| 首页 | 所有分区 | `src/data/landing.ts` 与局部常量同步维护中英文 |
| 复盘文档 | 12 篇正文 | 中文事实源 + 英文摘要，全文翻译渐进推进 |

## 8. 动效规范

- 只允许表达真实状态变化的动效：链路接通、消息前进、进度单调推进、数字首次计数；
- 首屏动画只播一次，总时长不超过 3 秒；
- 禁止视差、粒子、无限循环、随机漂浮和与机制无关的装饰动画；
- hover/focus 反馈控制在 160–200ms。

## 9. 验收

- `npm run typecheck` 与双语 `npm run build` 通过；
- 桌面与移动端无横向溢出、文字遮挡和不可达交互；
- 六步工作台可点击并可用键盘切换；
- Light/Dark、中文/English 均可用；
- 未实测指标始终显示待实测，不出现伪造数据；
- 控制台无未捕获错误，关键链接可达。

## 10. 边界

- 首页状态轨是机制演示，不连接真实后端；
- 性能采集脚本仍未落地，站点只展示占位与采集契约；
- 文档英文正文仍按篇推进；
- 当前站点不新增搜索服务、在线 Playground 或遥测。
